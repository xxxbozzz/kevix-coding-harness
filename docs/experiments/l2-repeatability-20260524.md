## Cache Hit Analysis

Final cache hit values:

```text
L2-001: 99.56%
L2-002: 89.74%
L2-003: 98.03%
L2-004: 90.09%
L2-005: 99.19%
```

Mean final cache hit:

```text
(99.56 + 89.74 + 98.03 + 90.09 + 99.19) / 5 = 95.322%
```

Interpretation:

- `cache_hit_final` differs by task because it is the cache ratio of the final API call, not a weighted full-task ratio.
- Shorter tasks such as L2-002 can finish before cache behavior stabilizes.
- Longer tasks such as L2-003 have more calls and more opportunity for prefix reuse.
- Tool results and gate events append new context, which can reduce the final-call cache ratio.

Future runner versions should additionally record:

- warmup-excluded average cache hit
- token-weighted cache hit
- cached prompt tokens and uncached prompt tokens
- task-level total tokens

## Gate Evidence

Gate events were observed in 4 of 5 tasks.

The most important qualitative finding is not only that gates blocked actions, but that the Worker recovered and still completed the task.

Examples from raw data:

```text
L2-001: [scope] bash: Bash command references path outside project
L2-003: [scope] bash: path outside project
L2-004: [scope] bash: path outside project (2 events)
L2-005: [scope] bash (2 events)
```

This supports the claim that the scope gate is not just a unit-test artifact; it intervened during real LLM-driven tool loops.

## Why This Matters

The previous L2 smoke test proved that Kevix could run one real end-to-end task.

This repeatability checkpoint adds evidence that:

- Controller to Worker flow can repeat across different task types.
- `manual` approval mode can coexist with real task execution.
- gate intervention does not necessarily break the workflow.
- DeepSeek provider path can survive multiple real tasks.
- the harness can complete small real codebase modifications without breaking build/tests.

## Limitations

This report should not be overclaimed.

Known limitations:

- only one codebase was used
- only small tasks were used
- `L2-001` was imported from a prior smoke run, not generated by the current runner
- no matched baseline was run against plain Claude Code or generic harness
- cache metrics are currently final-call ratios, not weighted token-level aggregates
- no public benchmark was used
